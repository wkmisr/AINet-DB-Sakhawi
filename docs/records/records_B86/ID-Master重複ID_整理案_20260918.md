> なお ID-Master 側の Note 欄への転記は行わず、drop 行の note は上記 TSV に全文保存する方式とした。


ID-Master を gviz 経由で全行走査したところ、**同一 ID が2行に登録されている箇所が12件**あった。
いずれも「名寄せの際に旧行を残したまま新しい行を足した」型か「表記ゆれを別行で登録した」型。

## なぜ問題か

- ブラウザ（`docs/browser/build.py`）の ID→名前の逆引きは**先に現れた行を採る**ため、どちらが採用されるかが行順に依存する。
- precheck の「登録名と記載名の不一致」判定も同様で、片方の行にしか別名が入っていないと偽陽性が出る。
- 実害は表示・検査のみで、XML 側の参照は ID で解決されるため壊れない。

## 整理案（keep = 残す行、drop = 削除する行）

削除は取り消せないため、**適用前に Waka の確認が必要**。
「alias」は keep 行の Arabic 欄に `|` 区切りで足す語。drop 行の note に固有の情報がある場合は keep 行の note に転記する。

## 手順（Waka 承認後）

1. keep 行の Arabic 欄に alias を `|` 区切りで追加し、drop 行の固有 note を keep 行の Note 欄末尾に転記する。
2. drop 行を削除する（行削除。行番号は上から順に削除すると下の行番号がずれるので、**下の行から削除する**）。
3. TSV エクスポートで、対象12 IDが各1行になったことと総行数が12減ったことを確認する。

※ 削除に抵抗がある場合は、drop 行の ID 欄を空にして Note に「重複のため無効（keep=行N）」と書く方法でも、逆引きとprecheckの問題は解消する（行は残る）。

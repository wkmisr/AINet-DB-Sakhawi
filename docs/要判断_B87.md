### ★ §E-6（規則25 候補）ルート直下 `event` / `state` の `@n` の振り方
- 【提起元】機械検査パス（派生検査）— 規則19が `relation` にしか言及していないことに起因
- 【論点】規則19は **`relation/@n` の規約A**（親族には振らない／非親族は通し番号）のみを定めており、**`event` と `state` の `@n` については何も言っていない**。
- 【現状の実測】B87 の全 79 event・33 state に `@n` はあり（欠落ゼロ）。ただし **6ファイルで `@type` ごとに振り直している**（例: `residence n=1` ＋ `cultural n=1` が同一ファイルに共存）。これは **repo 既存 1,253ファイル中 211ファイル（約17%）と同じ従来慣行**であり、機械検査は規則19の対象外として違反としなかった。残り約83%はファイル内通し番号。
- 【推奨】**規則25 として「`event` / `state` の `@n` はファイル内の通し番号とする（`@type` ごとに振り直さない）」を明文化する**ことを推奨。多数派（約83%）に合わせる形で、`@n` を「ファイル内でその要素を一意に指す番号」として統一できる。少数派211ファイルの一括是正は機械的に可能（`@n` は参照先を持たない属性なので付け替えても整合性は壊れない）。
- 【併せて】「振り直さない」で裁定される場合、B87 の該当6ファイルも同時に是正する（どのファイルかは機械検査パスが特定済み）。現状維持（両慣行を許容）でも実害はないため、**優先度は低い**。
- 【影響範囲】repo 211ファイルの `@n` 付け替え（機械処理）。データの意味は変わらない。

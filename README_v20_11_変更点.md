## 3. app.py の追加ガード（検疫パイプライン強化）

処理順（解析直後および「🔄 ID再チェック」ボタン）:
`立項番号ガード → 汎称語フィルタ → TMP検疫(既存) → wd/gn検疫(新設) → ID-Master照合 → NEEDID付与`

### 3-1.【新設】wd/gn 検疫 `verify_and_quarantine_wd_gn_ids()`
従来の TMP 検疫は wd:Q / gn: を素通ししていた（B19 で Q561280=Cassini がカーイトバーイに付与された穴）。
- **確定毒 Q-ID（denylist 15件）**→ NEEDID に差し戻し＋正候補を提示（例: Q208507→「候補: Q1023470」）。
- **ID-Master 登録済みの Q/gn** → 登録名（| 区切り別名含む）と不一致なら NEEDID（別item流用の検疫）。
- **照合済み allowlist**（handover v13.0 確定 wd 34件・gn 8件）→ 素通し。
- **未知の wd/gn** → 値は保持し「要 WebSearch 照合」として報告（正しい Q-ID を壊さない）。
- geonames 既知誤指しペア（سواكن→105299 等）も名前条件付きで検疫。

### 3-2.【新設】汎称語フィルタ `drop_generic_collective_entries()`
جماعة／غيره／آخرون／غير واحد 等が person 化されたエントリを除去
（B19実例: D02075 の جماعة→TMP-P-000004）。**ابن جماعة・عبد الله بن جماعة 等の実在家名は保護**。

### 3-3.【新設】立項番号ガード `scrub_entry_serial_artifacts()`
史料マーカーから立項連番を抽出し、(a) 訳文冒頭の裸連番を除去、(b) death_h/birth_h が連番と一致する場合は
**自動削除せず** cert=low 化＋note に CHECK を追記（偶然一致の可能性があるため最終判断は校閲者）、
(c)「831年…」「In 837, …」型は警告のみ。

### 3-4.【改修】ID-Master 照合の「|」区切り別名対応
「التقي بن فهد| ابن فهد」「الأزهر | جامع الأزهر」のような別名を個別キーとして登録。
→ 別名表記での照合取りこぼし・**正当な参照の誤検疫**を防止（テストT2で確認）。

### 3-5.【新設】検疫レポートの永続表示
従来は解析直後の警告が st.rerun で消えていた。メイン画面上部に
「🛡️ 検疫レポート」パネルを常設し、直近の検疫・除去・要照合の全件を確認済みにするまで表示。

### 3-6. バージョン表記
APP_VERSION = **v20.11** (2026-07-24)。XML の generated-by コメントにも反映（トレーサビリティ）。
